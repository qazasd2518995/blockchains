## 結論與範圍

先前的餘額保護不完整。已在本地修正以下可重現問題，尚未提交、推送或部署；本報告不代表正式站或整個平台已通過驗收。

範圍為 `fruit-mary` 原版 Cocos 水果機、React 容器及 Fastify 水果機服務。未變更機率引擎、賠率、控制規則、美術素材、解析度或動畫速度，未操作正式會員、餘額或控制設定。

## 已修正

1. 原版初始化使用 `parseInt`，分配工具也截斷小數餘額。現在以兩位小數保留權威錢包餘額，只有下注單位／比大小分配維持原本的整數操作。包含快取資源先完成初始化的情況。
2. 請求失敗時先恢復按鈕、後清除結算鎖，導致按鈕又被鎖住。改為釋放鎖後恢復，並讀取最新錢包、清除無法負擔的選注、保留合法的比大小狀態。
3. 比大小、收分與輪盤動畫完成事件可交錯，提早開放按鈕或允許重複操作。新增對應進行中狀態，等待原版完成回呼才恢復操作。
4. 原版自動下注用匿名延遲回呼；停止時取消具名函式並不會取消它。現在停止後會使已排程的下一注失效，但不取消其他延遲恢復工作。
5. 下注／比大小加入操作 UUID；同一次失聯重試讀取已提交結果，不再扣第二次。不同內容重用 UUID 會拒絕。使用專用 `/operations/spin`、`/operations/gamble` 路徑，避免舊 API 忽略 UUID 後重複下注；舊路徑仍相容但不具有新端點的強制 UUID 保證。
6. 接受結算後，重新載入及返回大廳需等權威餘額同步，不讓 session-ready 訊息誤解鎖。返回大廳不必等純展示動畫播完。
7. 手機版原版遊戲會讓 iframe 自行全螢幕，遮住外層重新載入與回大廳控制。嵌入模式改由平台容器管理全螢幕，單獨開啟仍保留原行為。
8. 權杖刷新加入 15 秒逾時；比大小 API 拒絕超過兩位小數的金額。更新前端快取版本。

## 部署注意

先部署 API 的新操作端點，再部署 Web。若新 Web 先遇到舊 API，操作端點會 404 並安全拒絕，而非退回可能重複扣款的舊路徑。現有資料模型已有操作 ID 唯一索引，本次未新增 migration。

部署後仍需檢查實際載入的 adapter v18、boot v5、容器 v8 與新端點，使用隔離測試帳號驗證最後一注、失聯重試及回大廳餘額。不能宣稱已排除所有裝置、網路或整个平台問題。
